# Mac App Store対応に向けた入力経路の調査

この文書は、Mac App Store版の設計に向けて既存実装の入力経路を確認した記録です。対象は `ab69e37` のソースコードであり、サンドボックス内での動作、署名、Appleの審査適合性を実証したものではありません。`~` は利用者のホームディレクトリを表します。ここに記載する場所は既定値であり、実際の存在やアクセス可否を確認したものではありません。

## ローカル集計

本体の `Sources/AIMeter/LocalUsageCollector.swift` は、有効なサービスを対象に一回の収集を行い、サービスごとのカスタムパスを受け取ります。現行のインターフェースは一つのサービスIDに対して一つのパスを渡します。以下の「別経路」は、カスタムパスを指定しても既定のホーム配下の参照が残るため、ストア版の設計で個別に扱う必要があります。

| サービス | 現在の主な入力 | 別経路と補足 |
| --- | --- | --- |
| Codex | `~/.codex/sessions` 以下のJSONL | カスタムパスはこの収集元を置き換える。 |
| Gemini / Antigravityログ | `~/.gemini/antigravity/brain` 以下のトランスクリプト | カスタムパスはbrain側のみを置き換える。`~/.gemini/tmp` 以下のチャットJSONも別に参照する。残量のローカル通信は後述の別連携。 |
| Claude Code | `~/.claude` 以下のJSONL | 主経路内の `.claude.json` に加え、必要に応じて `~/.claude.json` を参照し、プラン表示や集計の補完に使う。 |
| Grok Bot | `~/Library/Application Support/Grok Bot/sand-client-persistence` 以下のblob | `~/.grokbot` の存在も確認する。blobの使用量キャッシュやトランスクリプトから集計する。 |
| GitHub Copilot | `~/.copilot/session-state` 以下の `events.jsonl` | カスタムパスはこの収集元を置き換える。 |
| Windsurf | `~/Library/Application Support/Windsurf/User/globalStorage/state.vscdb` | ファイルまたはその親ディレクトリをカスタム指定できる。読取時には存在する場合に隣接する `state.vscdb-wal` も確認し、DBとWALの私有コピーを使う。 |
| Cursor | `~/Library/Application Support/Cursor` 以下のAgentStores | `~/.cursor` の存在も確認する。AgentStoresの制御ディレクトリがあればそちらのJSONを数える。 |

Grok Botの `~/.grokbot` とCursorの `~/.cursor` は上記の収集関数では存在確認に使われ、記載した主経路とは扱いが異なります。サービス検出には別途、各サービスの関連ディレクトリの存在確認があります。詳細は `LocalUsageCollector.swift` の `detectInstalledProviders` を参照してください。

既存の `BoundedInput` は走査件数、読取量、時間を制限し、シンボリックリンクを走査対象から除外します。ファイルの通常ファイル確認やWindsurfの私有コピーも、アクセス方法を変更する際に維持すべき既存の保護です。入力が存在しない場合に空の結果を返す箇所があるため、許可不足、データなし、一部経路のみ取得できた場合を正しく区別できるかは別途検証が必要です。

## 通信・外部プロセス・保存

| 連携 | 現在の実装 | ストア版での確認事項 |
| --- | --- | --- |
| OpenAI API | 任意の連携として `api.openai.com` の組織利用量・費用APIにHTTPSで照会し、キーはKeychainで扱う。 | サンドボックス下のネットワーク権限、ストア版独自のKeychain識別、拒否・再設定を確認する。 |
| Google Cloud Monitoring | `gcloud` を外部プロセスとして起動してアクセストークンを取得し、`monitoring.googleapis.com` へHTTPSで照会する。gcloudの設定場所にも依存する。 | 外部実行、設定アクセス、認証、通信がサンドボックスで成立するか未検証。 |
| Antigravity残量 | 別プロセスを検出し、`ps` と `lsof`、プロセス・署名・ソケット検証を経て同じMacのloopbackへ接続する。 | プロセス情報の取得と接続・検証がサンドボックスで成立するか未検証。 |
| GitHub版の更新 | GitHub Releasesの情報と配布物を取得し、検証後にアプリを差し替える。 | ストア版ではこの更新経路を使わず、GitHub版は従来の経路を維持する。 |

現在の `KeychainHelper` はサービス識別子 `com.local.AIMeter` を使用します。別Bundle IDだけで設定や認証情報の分離が十分とは判断せず、ストア版独自の識別と実際のKeychainアクセスを合成データで検証します。現在の本体とWidgetはホーム配下の表示用ファイルを共有し、Widgetにはその読取例外があります。ストア版ではApp Group共有を別途設計し、実署名された本体とWidgetで確認する必要があります。

## 実施前の確認

- 独立レビューで、選択ディレクトリ配下の固定中間パスを検査した後、その親がシンボリックリンクに差し替わると、URLベースの走査が選択範囲外へ及び得ることが判明した。静的なリンクの拒否だけでは競合を防げない。Store用収集を実画面へ接続する前に、ディレクトリ記述子を起点とする競合に強い走査・読取を実装し、全入力経路で合成テストする。対応できない入力はStore版で未対応として扱う。
- `StoreScopedDirectory` は `lstat` と `fstat` の間の最終要素の置換を拒否する試作だが、最初の `lstat` より前に選択先や祖先が置き換わる場合、bookmarkの選択対象と実際に開いたFDの同一性を証明しない。scope内でFDを保持しFD相対で読むだけでは、この最初の結び付けを検証したことにならない。実署名Sandboxでの置換・移動・失効の確認と、成立しない場合の再選択または非対応の扱いを確定するまで本番へ接続しない。
- Store用の試作収集入口は、空・誤選択・解析不能と正しい集計0を識別できない。入力ごとの判定を実装・検証するまで、返った数値を成功結果として表示・保存しない。
- CodexのFDベース試作は、同一ファイル中で累積値が減少するか、キャッシュの増分が入力の増分を超えた場合、その行以降を集計せず部分結果とする。最後の有効値を基準として保持するが、そのファイル内では再開せず、別ファイルからのみ新しい基準で収集する。直接配布版の既存集計方法は変更しない。
- Codexの利用枠情報は、最新イベントが一部の枠を省略したとき、その枠が「変更なし」なのか「取得できない」のかの正式仕様を確認できていない。現時点では古いイベントの枠を補完せず、最新の有効イベントだけを使う。したがって利用量が完全と判定されても、全利用枠の完全性を保証しない。利用枠だけで使用量がない場合は試作の結果型で区別し、使用量を未取得とするが、表示には未接続。Store版へ接続する前に仕様と表示方法を確認する。
- GeminiのFDベース試作は、トークン情報がない一部のbrainログで本文の文字数から使用量を推定する。推定を明示する表示・状態は未接続。chatsの `total` とinput/outputの関係は実データの仕様を確認できておらず、既存版と同じ計算を使うことだけでは数値の正確さを証明しない。複数rootのentry数・file数も合算して制限する設計だが、実Sandboxでは未検証。
- 合成データで、各収集経路の許可、複数経路の部分許可、拒否、移動、再起動後の再アクセスを個別に確認する。WindsurfはDB単体とWALがある場合を含める。
- 取得できない連携をゼロや未検出と誤表示しないことを、本体とWidgetの双方で確認する。
- 実ログ、実API資格情報、実サービスとの接続、Intel、macOS 14、実WidgetKit、App Store審査はこの調査では未検証。検証できた条件と未検証の条件を別々に記録する。
