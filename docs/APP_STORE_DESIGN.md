# Mac App Store版の設定体験と実装条件

この文書はStore版の設計中の記録です。Store版の動作、Apple審査、利用者による評価を示すものではありません。GitHub版は別に維持し、Store版では設定やAPIキーを最初から入力します。

## 目的と対象

利用者が必要なサービスだけを選び、どのデータを読むのかを理解して利用量を確認できることを目指します。初回の開始前にログを読まないこと、サービスごとに収集を停止できること、推定・未取得を区別することを維持します。Store版は無料・日本語・日本向けを予定しています。

現状の自動検出は操作が少ない一方、サンドボックスで許可されていない場所の未検出と実際のデータなしを区別できません。全サービスを一度に許可する方法は範囲の理解と復帰が難しくなります。Store版では、選んだサービスに必要な場所だけを順に説明し、それぞれを選択できる案を採ります。後回しを許し、一つのサービスの結果を得てから残りの設定に戻れる設計とします。実際の負担は人による確認が必要です。

## 状態と操作

- サービスごとに、各入力元の目的、読み取り対象、許可状態を示す。複数経路がある場合は個別に選択でき、親フォルダ全体への許可を無条件に求めない。
- 許可と収集結果は別々に扱う。一部許可のまま取得に成功した場合は、欠けている入力元と部分的な結果であることを示す。読み取り不可をデータなしと断定しない。
- 選択パネルのキャンセルは、既存の許可解除と区別する。キャンセルや後回しによって、他のサービスの設定や利用を妨げない。
- 以前の結果がある場合は、最終成功時刻と現在の許可・取得状態を示す。権限失効や移動時は、対象の入力元だけ再選択を案内する。利用可能な履歴がない場合は数値ゼロを未取得の代わりに表示しない。
- 確認済みの非対応連携は、サービス選択前に何が利用できないかを示す。正常に取得できるサービスは結果と更新時刻を中心に、操作が必要な項目を優先して表示する。
- GitHub版とは別アプリであり、設定・履歴・APIキーを引き継がないことを導入前に示す。既存版やデータの削除は行わない。

権限と取得結果はそれぞれ独立して保持し、部分取得・古い結果・取得失敗をWidgetにも正しく伝えられるようにする。各サービスの入力経路は [入力経路の調査](APP_STORE_SOURCE_AUDIT.md) を参照する。入力範囲・表示文言・非対応の判断は実際の動作検証後に確定する。

### 入力元ごとの状態

| 軸 | 状態 | 表示と操作 |
| --- | --- | --- |
| 許可 | 未選択 | 理由と対象を表示し「選択」または「後で設定」を選べる。 |
| 許可 | 許可済み | 対象名を表示し「変更」と「解除」を選べる。 |
| 許可 | 要再選択 | ブックマークの解決、アクセス開始、対象の移動・削除、更新に失敗した場合に表示する。原因が特定できない場合は断定せず「再選択」を案内する。 |
| 許可 | 解除済み | 自分で解除した対象について「選択」を表示する。解除した入力を以後の集計から除き、残る許可済み入力で再収集する。以前の合算値は部分結果として流用しない。 |
| 収集 | 未実行・取得中 | 取得前は未取得、処理中は取得中とする。 |
| 収集 | 成功 | 対象の妥当性を確認して走査・解析できた範囲と最終成功時刻を示す。正しく完了した集計のみ、該当件数が0なら0件とする。成功は全経路の完全性を保証しない。 |
| 収集 | データ未検出・対象不適切 | 対象が正しいと確認できない、または有効データを検出できない場合は、数値0とせず場所の確認・再選択を案内する。 |
| 収集 | 失敗 | 取得失敗と再試行を示す。以前の結果は最終成功時刻と古い値であることを添える。 |

選択パネルの取消は状態を変更せず、それ以前の許可を保持する。設定を後回しにした対象はサービス連携設定から選び直せる。選択したURLは読み取り専用のsecurity-scoped bookmarkとして保存し、各収集の間だけアクセスを開始して終了する。再起動時にブックマークを解決し、staleなら安全に更新する。保存、解決、開始または更新に失敗した入力元は許可済みと扱わず再選択を促す。

収集中にサービスを無効化または許可を解除した場合、操作時点で処理を取り消し、処理完了が遅れても旧世代の結果を保存・表示しない。サービス全体がオフまたは主要入力がすべて未許可なら数値を表示しない。別の入力元が許可済みなら再収集後に部分結果を表示する。以前の集計データは削除せず、再有効化後は新しい許可状態で収集し、更新前の値を最新結果と見せない。拒否と取消はOSから区別できる場合のみ区別し、判別できない失敗は原因を断定しない。

### 入力範囲と部分結果

| サービス | 主要な入力元 | 補助入力・不足時の扱い |
| --- | --- | --- |
| Codex | sessions | 未許可ならCodexのローカル使用量は未取得。 |
| Gemini | Antigravity brain、Gemini chats | それぞれ個別に選択する。片方のみの場合は該当ログのみの部分集計とし、もう片方の欠落を示す。 |
| Claude Code | Claudeログ | 選択済みログディレクトリ内の設定JSONを優先し、存在せず別のホーム直下のJSONも必要なら個別に許可する。未許可なら暗黙に参照せず、ログ由来のみの集計とし、設定JSON由来のプラン・補完がないことを示す。 |
| Grok Bot | persistence | 補助の存在確認先がなくても主経路を取得できる場合は存在確認に依存しない。主経路未許可なら未取得。 |
| Copilot | session-state | 未許可ならローカル使用量は未取得。 |
| Windsurf | state.vscdbと隣接WALを含むディレクトリ | DBとWALの読取成立を先に検証する。WALを安全に扱えなければその結果を最新として表示しない。 |
| Cursor | AgentStoresを含むCursor保存先 | 補助の存在確認先がなくても主経路を取得できる場合は存在確認に依存しない。主経路未許可なら未取得。 |

各サービスは主要入力元を最低限必要とし、全入力元が未許可なら未取得と選択操作を表示する。主要入力が複数あるGeminiでは一部取得を許すが、その範囲を明示する。各入力元の安全な選択単位やSandbox上のアクセス可否は合成データで検証し、成立しない場合は対応範囲に含めない。

本体では部分取得と古い結果の両方を値・最終成功時刻に付けて表示する。Widgetも同じ区分と時刻を共有し、未取得・表示停止は数値を出さない。古い部分結果なら両方を示し、スペースが足りない場合は数値より状態を優先する。共有に必要な情報だけをApp Groupへ渡し、Widgetがログや権限を直接扱わない。

## 審査と検証

2026-11-10に、対象コミット `ab69e37` と初回設定案を使い、作成担当の会話履歴を渡さない別担当によるソースベースのUX審査を実施しました。結果は必須修正ありで、許可状態と収集結果の分離、複数入力元、キャンセル時の既存許可の保持、非対応機能と移行なしの事前説明が必要と判定されました。上記設計に反映していますが、この改訂版の再審査は未実施です。

改訂版の再審査では、状態遷移、ブックマーク復元、入力範囲、Widgetの表示対応を具体化しました。さらに部分解除時の再収集、0件と対象不適切の分離、Claudeの補助JSONの優先順位を追記しました。会話履歴を分離した同じ審査者が追記差分を再審査し、この状態・操作設計の範囲では本実装前の必須指摘は解消と判断しました。技術・配布審査や実機確認の合格を意味しません。

実装後は合成データを用い、初回、再起動、部分許可、拒否、選択の取消、ファイル移動、失効、再許可、ゼロ件、古い結果を確認します。人による初回・反復操作の観察と、署名済みStore版のサンドボックス・実WidgetKit検証は別途必要です。
