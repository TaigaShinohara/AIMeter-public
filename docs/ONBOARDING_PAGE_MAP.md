# 初回オンボーディング ページ地図

`mobile_onboarding` スキル（TaigaShinohara/mobile-onboarding 0.5.0）の様式で、macOS版AIMeterの初回体験（`CollectionIntroductionView`）を設計した地図。実装はこの地図を正とする。

## 前提（コンセプトの読み取り）

- コンセプトは資料（README、docs/APP_STORE_DESIGN.md の目的文）からの読み取りで、本人の一文確定は未実施（独立審査 R-2 のまま）。この地図はその範囲の仮説として扱い、確定後に文言を再照合する。
- 4条件の具体化:
  - 何のためのアプリか: 「AIツールの残量を、メニューバーで一目で確かめるアプリ」と自分の言葉で言えること
  - スリーステップ: ①集めるサービスを選ぶ ②「使い始める」を押す ③メニューバーで残量を見る
  - ワクワクの山場: フックのリボ登場（1ページ目）と、期待ページのWidgetモック（11ページ目）。最後だけに置かない
  - 最初の小さな成功: 接続ページで開始した直後、本体の残量表示が出ること
- プライバシー契約は不変: 開始ボタンを押すまでログを読まない。ページ送りや選択では収集を開始しない。悩み・希望の選択は端末内（UserDefaults `onboardingConcernV1`）にだけ残し、外部送信も計測連携もしない。

## macOSへの適合（モバイル前提からの置き換え）

- ページ送りはスワイプではなく「次へ／戻る」ボタンと自動遷移（選択ページ）。ボタン位置は全ページで固定する
- 触覚は macOS 標準の `NSHapticFeedbackManager` に読み替える（小=levelChange、中=alignment、大=generic）。トラックパッドのForce Touch環境でのみ返る、端末設定に従う
- 大（完了）の祝いアニメーションは入れない。開始を遅らせる演出を避け、祝いは本体の初回表示そのものに委ねる（スキル側の「次の操作を塞がない」条件を優先した判断）
- 接続ページには従来の開示文（読み取る内容／保存と通信／表示の意味／いつでも停止）を残す。これは請求や同意に準じる「真剣な内容」として、1主張ルールの例外ではなく接続ページの補足情報として同居させる（従来表示の後退を避けるため）

### 価値ページの並べ替え（選択の使い道）

- 悩み・希望の選択肢と、マッチで挙げる強み、価値ページの並び:
  - 「気づいたら上限に当たっていた」→ 強みはリボの先回り通知。価値は [一目で分かる, 分けて見せる] の順
  - 「残量を確かめるのに、いちいち開いている」→ 強みはメニューバー集約。価値は [分けて見せる, リボの通知] の順
  - 「推定の数字を、どこまで信じていいか不安」→ 強みは公式・目安・未取得の区別。価値は [一目で分かる, リボの通知] の順
  - 「まだわからない」→ 宣言は断定せず誘いの形。価値は標準順 [一目で分かる, 分けて見せる]
- 10の選択は `showOpenAISection` / `showGeminiSection` に即反映され、12のトグルで最終確認・変更できる

### 進捗（窓ドット）

- 最大5つ表示、現在を中心に窓がスライド、端は小さく。数字表記なし、タップでジャンプ不可。読み上げでは総数を出さず、見出しで現在地を伝える（パターン集の仕様どおりに実装）
