# 表示情報の整理

対象：初回導入、本体・メニューバー、一般設定、サービス連携、制限と予算、ヘルプ、Storeの読み取り先、Widget。
基準：`ART_DIRECTION.md` 1.0 の「静か・正確・親しみ」。既存の標準フォーム、ゲージ、表示切替、DisclosureGroupを流用する。色・角丸・書体を増やさない。

## コンセプトと画面の主役

READMEとアート方針から、AIツールを使う人が作業の合間に利用状況をまとめて確認し、残量と取得状態を把握できることを軸にする。最優先は短時間での正確な把握。

| 画面 | 主役 | 狙う状態と手段 |
| --- | --- | --- |
| 初回 | 集計開始までの選択 | 概要、表示、集計対象の3段階。開始前の同意を短く常設する |
| 本体・メニューバー | 気にするべき残量・取得状態 | リボの案内とサービスのゲージ。補足は情報ボタンへ |
| 一般 | 変更する設定 | 設定操作を先にし、保存仕様は開いて読む |
| サービス連携 | 有効状態と読み取り先 | 任意API・キー保守は折りたたみ、エラーは常設する |
| 制限と予算 | 選択したサービスの上限 | 期間と値の標準フォームを維持する |
| ヘルプ | 調べたい質問 | 検索と閉じた質問を先に置き、データ取扱いと連絡先を後に置く |
| Store読み取り先 | 選択状態と選択操作 | 同意・未確認・回復は残し、操作のヒントだけ畳む |
| Widget | 残量、期間、鮮度 | 現行構成を維持。未知を0%にしない |

## 同じ場面での仕分け

各行を情報または操作のひとまとまりとして数える。必須が失われる条件、支援の助け先、ノイズの処置を同じレイヤーで比較する。以下は今回変更するまとまりの監査であり、アプリ内の全要素数ではない。

| 場面 | 必須・支援と根拠 | ノイズと処置 |
| --- | --- | --- |
| 初回・説明 | 概要：用途が分からなくなる。表示選択：利用状況の見方を支援。集計対象と開始：同意が成立しなくなる | 悩みアンケート、マッチ宣言、価値の反復、3ステップの再説明、試し操作の結果再掲、期待の宣言：削除 |
| 初回・反応 | 選択状態と戻る・次へ：行為の結果と現在地を支援 | 称賛バナー、成功触覚、自動送り、装飾の周期運動：削除 |
| 通常・操作 | 上部の設定ボタン：回復先。ウィジェット表示、終了：ウィンドウの管理を支援 | 下部の同じ設定ボタン：削除 |
| 通常・状態 | 期間ごとの残量／未取得：不明な値を区別できなくなる。詳細のデータ元とリセット：解釈を支援 | 見出しの未取得と各行の未取得の重複、詳細末尾の同じ定義の再掲、キャラクター名の常設：削除 |
| 一般・補足 | 数値表示トグル：表示を選べなくなる。共有ファイルの保存仕様：その選択を支援 | トグル直下の長い常設説明：支援として折りたたむ |
| サービス・補足 | 有効スイッチ、読み取り先、保存とエラー：接続・停止・回復ができなくなる。任意API・キー保守：収集と保管を支援 | 設定する前から並ぶ任意APIと保守の説明：支援として折りたたむ（失敗状態は外へ出す） |
| ヘルプ・質問 | 検索とFAQ：解釈・回復を支援 | 同じ質問の別実装、質問より先のアプリ紹介と常設長文：質問を一元化、紹介を削除、取扱いは折りたたむ |
| Store・補足 | ログの内容、保存選択と読み取り未確認、選択しない場合：許可の判断を支援 | どの選択前にも出る隠しフォルダの操作説明：操作ヒントとして畳む |

ノイズとして数える項目は上表の明示した反復・演出のみ。支援情報の折りたたみを削除と数えない。初回の用途説明と最終画面の同意は別の判断に必要なので残す。任意で開くヘルプ・詳細の再説明は自発的な見返しとして残す。

## 比較と実装判断

- 現状維持：全機能に届くが、初回は14ページで価値説明と称賛が続き、最初の残量まで遠い。
- 1画面への統合：短いが、概要・表示・同意が348pt幅で競合するため採らない。
- 3段階へ削減：用途→表示の実例→収集対象と同意に分ける。アンケートでの説明順の個別化はなくし、既存の設定画面から表示を選べる。保存済み設定は勝手に変更しない。
- Widget・制限と予算：比較に必要な期間・値・鮮度を既に分離しているため維持する。件数を減らすための変更はしない。

独立設計審査の条件 N1〜N7（サンプルの真実性、開始同意、保存設定維持、配布別ヘルプ、未知の保持、エラーと回復、設定導線）を採用して実装する。主担当はこの範囲の実装開始を判断。上流コンセプトは維持する。参照先の independent-review / experience-balance と保存版マニュアルはこの環境では見つからず、別担当で目的・周辺影響・UI・実装を直接審査する。

新しい独自UIは作らない。初回のプレビューには実在の `ProviderUsageSection` と `UsageDisplayModePicker` を使い、既存の別実装ミニメーターをなくす。FAQは既存の質問を共通データに寄せる。新たな機能・API・収集範囲は追加しない。

## 到達性と検証

数値の保存仕様は一般設定から1回、任意APIと保守はサービス選択後1回、データ取扱いはヘルプから1回の展開で届く。エラー・保存未完了・Widget共有未適用・削除確認を隠さない。初回の前後移動・スキップ・全オフ・表示選択では収集を開始せず、開始操作だけが同意を保存する。

比較用画像は合成データのみで生成する。明暗、数値ON/OFF、公式・目安・未取得・混在・長文・失敗、標準フォームと開閉状態を確認する。人間の3秒理解、VoiceOver実操作、実Widget、Intel、旧macOSは別の確認であり、画像やbuildの成功で代用しない。

| 初回の悩み選択肢 | 4 | 0（表示モードの2択は残す） |
| 初回の称賛の強さ・触覚 | 3段階 | 0 |

| 同じカードの設定導線 | 2 | 1 |
| FAQのデータ定義 | 2種類 | 1種類 |
| アップデートの版情報の行 | 2 | 1 |
| 最終同意ページの可視文字（通常版、称賛なし） | 161文字・10まとまり | 141文字・9まとまり |

文字は表示文字列のUnicode文字数（空白・句読点・ナビゲーションを含み、アイコン・読み上げ専用名を除く）。前はスキップで到達した最終画面、後は3ページ目を同じCodex/Gemini選択状態で比較する。後はheadline・callout・captionの3階層。カラーは既存の主色・補助色、標準の面を流用し、新しい色役割・角丸・フォントサイズは追加していない。

ノイズ率は全アプリの推計ではなく、上表の仕分けに対応する固定標本で比較する。情報レイヤーの14項目は、必須・支援8項目（概要、値の根拠、期間と残量、詳細のリセットと参考額、更新状態、開始同意、キー状態、FAQ回答）と、ノイズ6項目（マッチ宣言、称賛、期待宣言、試し操作の結果再掲、見出しの未取得、詳細末尾の定義再掲）。整理前6/14（43%）、整理後0/8。操作レイヤーの7項目は、必須・支援5項目（前後移動、表示選択、サービス選択、明示開始、上部設定）と、ノイズ2項目（悩み選択、下部設定）。整理前2/7（29%）、整理後0/5。これは監査標本内の率で、残った全画面にノイズがないという証明ではない。

Swiftの全509テストは3件スキップ・失敗0。Store条件の本体コンパイルも成功。Pythonは81件中80件成功・1件エラーで、既存テストが以前に撤去されたStoreBuildGuard.swiftを参照するため。HEADでも同ファイルが存在せずテストが未変更であることを確認し、今回のUI変更には混ぜない。

独立レビューは設計と実装に対して実施。開始ボタンの「収集せず」という断定を指摘され、中立な「使い始める」へ変更して解消した。新たな修正必須指摘はなし。

アート方針との照合：色は既存のシステム色のみ、形は標準GroupBox/Form、文字は既存の3階層、初回の演出は静止、通常のリボは従来の動き低減対応を維持。コード上の照合は合致。合成のオフスクリーン画像で配置と文章量、質問を主役にする順序を確認した。ImageRendererは一部の標準部品を描画できないため、標準部品を含む画像にはNSHostingViewを使用。AppKitとSwiftUIの明暗を揃えたが、ネイティブタブの選択部は黒い矩形が残るため、その色とラベルの可読性は画像で確認済みとしない。設定の展開操作・フォーカス順・VoiceOver実操作、人間の3秒理解、実Widget・Intel・旧macOSは未確認。
