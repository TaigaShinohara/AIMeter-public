# アート方針：AIMeter

- 版：1.0
- 決めた日：2026-11-16
- 出どころ：既存コンセプト・設計ドキュメント（`README.md`、`docs/LIQUID_GLASS.md`、`docs/CHARACTER_SUMMARY.md`、`docs/WIDGET_LAYOUT.md`）からの導出
- 対象：アプリ全体の UI（デスクトップ本体、メニューバー、設定、ヘルプ、初回導入、LiquidBall、WidgetKit）

## 1. 世界の言葉

- 雰囲気キーワード（3つまで）：**静か、正確、親しみ**
- やらない雰囲気：**騒がしい、過度な装飾（全面ガラスや独自クロム）、曖昧な数値表現**
- 一文で言うと：**作業の邪魔をせず、必要な残量と注意点だけを静かに・正確に・少しの温かみとともに伝える macOS 標準の計器。**

## 2. 根拠マップ（コンセプト → アートの選択 → 理由）

| コンセプトの要素 | アートの選択 | 理由 |
| --- | --- | --- |
| 開発者が作業の合間に残量を確認する | macOS 標準のウィンドウ・フォーム・余白・Calm System Palette | 作業中の他アプリや OS の空気と馴染み、視線を奪いすぎず短時間で読めるため |
| 複数ツールの公式値・目安・未取得が混在する | 等幅数字の桁揃え、標準 `Gauge`、状態ごとの明確なラベル・警告色 | 数値の誤認を防ぎ、公式値と推定値をひと目で見分けられるようにするため |
| 残量低下や鮮度不足を気づかせたい | LiquidBall（リボ）の透明な球体と目＋短いひとこと案内 | 警告だらけの冷たいダッシュボードにせず、ひと目で「今気にするべき1点」を伝えるため |

## 3. 色の性格

- **主色の役割と性格**：`providerAccentColor`（macOS システムカラーの落ち着いたパレット：teal, blue, orange, cyan, mint, indigo, purple）をサービス識別のためにのみ使う。画面全体を派手に塗らず、アイコンやゲージのアクセントに留める。
- **補助色の役割**：警告・注意（15%未満の赤系、35%未満の橙/黄系）は「今すぐ確認すべき残量低下・鮮度不足」にだけ使い、通常時は中立色（`primary` / `secondary`）で静かに保つ。
- **背景と文字の関係**：OS が提供する標準背景（ウィンドウ、メニューバー、グループ化フォーム、`controlBackgroundColor`）を使い、文字は `primary` / `secondary` で十分なコントラストを確保する。
- **色を増やすときの決まり**：新しいサービスや状態を追加する場合も、既存のシステムカラー役割で表現できないか先に確認し、無意味な独自 RGB 値を増やさない。
- **やらない色使い**：情報カード全面への着色、意味のない画面ごとの色変更、未取得を 0% と同じ警告色で塗ること。

※ 具体的な実装値は `Sources/AIMeter/LiquidGlass.swift`、`Sources/AIMeter/SettingsStyle.swift`、各 View のシステムトークンを正とする。

## 4. 形の言語

- **角丸の方針**：macOS 標準の `GroupBox`、ポップオーバー、フォーム、Widget の `containerBackground` が持つ角丸に従う。独自角丸を作る場合も控えめな標準半径に揃える。
- **線と境界**：余白と面（`GroupBox`、Grouped Form `Section`）で情報を分ける。不要な独自の区切り線や70ptの空白は置かない。
- **影と立体**：基本はフラットな OS 標準面。LiquidBall（リボ）の球体のみ、ネイティブ Liquid Glass（macOS 26+ `clear`）と固定位置の柔らかい影で立体感を持たせる。
- **アイコンのタッチ**：SF Symbols（システム標準の線画・塗り）を統一して使う。独自イラストは LiquidBall（球体と2つの目）のみに限定する。

## 5. 文字と密度

- **フォントの性格**：システムフォント（SF Pro）を基本とし、数値・割合には等幅数字（monospacedDigit）を用いて桁を揃える。
- **文字の階層の原則**：主役（最も気にするべき残量・割合）＞ 補助（サービス名・期間・リセット時刻）＞ 注記（公式/目安/鮮度・ヘルプ補足）の3段階に抑える。
- **密度の方針**：348pt 幅（本体・メニューバー）および Widget 小・中・大で、長文は折り返し、行間と余白のリズムを崩さない。設定画面は `Form(.grouped)` の標準余白に従う。
- **1画面の情報量の目安**：開いて3秒以内に「今どのサービスがどれくらい残っているか」「次に何を見るべきか」が分かる量に収め、詳細はポップオーバーや `DisclosureGroup`、別タブへ逃がす。

## 6. 動きの性格

- **動きの性格**：穏やかで控えめ。作業の視線を奪わない。
- **動きを入れてよい場面**：LiquidBall の浮遊（約4.8秒周期・±2pt）と短いまばたき（約5.6秒ごと）、更新中の `ProgressView`、状態遷移の標準アニメーション。
- **やらない動き**：ツールバーボタンの独自ホバー拡縮、意味のないループ演出、操作を待たせる演出。
- **動きを減らす設定への対応**：`accessibilityReduceMotion` が有効な場合、LiquidBall は静止表示とし、不要なアニメーションを止める。ウィンドウ非表示・最小化・遮蔽時も動きを止める。

## 7. 良い例／悪い例

- **良い例**：
  - `DesktopMeterView` / メニューバー：`CharacterSummaryView`（リボ＋ひとこと案内）を最上部に置き、その下に `GroupBox` によるサービス一覧、詳細はポップオーバーへ逃がす構成。
  - `SettingsView`：`NavigationSplitView` + `Form(.grouped)` + `LabeledContent` による macOS 標準設定。
  - `WidgetViews`：小・中・大で比較軸（バーの左右端と率の右端）を揃え、期間と使用量を独立領域に分離した構成。
- **悪い例（過去に撤去・禁止した方針）**：
  - 背景の透明化や独自ヘッダー・70ptの空白・独自区切り線。
  - 情報カード全体への Liquid Glass 一律適用（非前面時に目が隠れる・可読性が落ちる問題）。
