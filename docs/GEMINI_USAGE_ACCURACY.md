# Geminiの推定使用量と残量

Geminiのローカルログから取得する使用量は推定値です。ログの使用量、GCPのAPI利用量、手入力の上限から、サービスの公式残量を作ることはありません。公式残量を取得していない枠は「未取得」とし、推定使用量は参考情報として残します。

Antigravityが返す公式残量は別の連携・カードです。[Antigravity連携](ANTIGRAVITY_QUOTA.md) を参照してください。

## ログの重複処理

同一sessionの通常transcriptとfull transcriptでは、canonical JSONのmultisetを照合し、最大出現回数を残します。片側にしかないevent、同一ファイル内の反復、別sessionの同文は削除しません。raw・effective・costは同じ選別済みeventから計算します。

payloadの異なるコピーは、安定したevent IDが保証されないため別記録として扱います。この処理は、実際の利用量やサービス側の請求との一致を保証しません。

## 表示する状態

- 公式値、設定上限からの目安、未取得を共通モデルで区別します。
- Geminiの未取得枠には割合・残量バーを出さず、逼迫順位や0%警告にも含めません。使用量の表示がONなら、推定使用量を表示します。
- 他サービスの設定上限から算出する割合は「約」を付けます。
- 真の公式0%は0%のまま保ち、数値エラー・更新失敗・未取得とは分けます。
- 全枠が未取得でもサービス自体は残します。旧Widget cacheにあるGeminiの算出割合は未取得へ移行します。

## 検証

合成データで、重複、JSONキー順、片側だけのevent、反復、別session、costの一致を確認します。表示の回帰テストでは、公式0%、未取得、数値エラー、更新失敗、メニューバーの各モード、旧Widget snapshotの移行・保存再読込、使用量表示OFF/ONを確認します。

テストには個人ログ、利用量、実際の画面画像を使用しません。WidgetKitの実表示、実際のVoiceOver音声、最低対応OSとIntel実機の動作は、合成テストと分けて確認してください。
