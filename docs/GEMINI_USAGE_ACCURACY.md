# Geminiの集計と残量表示

Gemini / Antigravityのローカルログから推定使用量を集計します。
この集計はGeminiの公式な利用可能量・残量を取得するものではありません。
ローカルログ、GCPの使用量、手入力した上限から公式の残量割合を作ることはありません。

## ログの重複処理

同じセッションの`transcript.jsonl`と`transcript_full.jsonl`には、同じイベントが
重複して記録される場合があります。AIMeterは次の条件でコピーを除外します。

- 同一セッション内でJSONのキー順を正規化し、内容の一致を判定します。
- イベントごとに両ファイルでの出現回数を照合し、大きいほうの出現回数を残します。
- 片方のファイルにしかないイベント、同じファイル内の反復、別セッションの同文は残します。
- 内容の異なる記録は、同じイベントであることを示す安定したIDが保証されないため、
  保守的に別記録として扱います。
- 生のトークン数、重み付き使用量、参考コストは、同じ選別済みイベントから計算します。

この照合で扱うのは通常とfullのtranscript間のコピーです。内容が変わったコピーや、
別形式のログを横断したすべての重複を識別することは保証しません。

## 使用量と参考コストの制約

ログにトークン数がある場合は、その値を使って集計します。トークン数がない記録は、
本文やthinkingの文字数から推定します。重み付き使用量とAPI換算コストにはアプリ側の
計算式を使用するため、サービスの公式請求額や契約上の消費単位と一致するとは限りません。

探索するファイル数、入力サイズ、行長、数値には上限があります。上限超過などで収集が
失敗した場合は、以前の集計ファイルを保持し、更新失敗の状態を表示します。

## 残量の状態

- Geminiの公式残量は未取得として扱います。推定使用量が設定上限を超えていても、
  公式残量0%には変換しません。
- 未取得の残量には割合・バー・上限を表示せず、逼迫順位や残量警告から外します。
  使用量の表示をONにした場合は、取得できた推定使用量を参考情報として表示します。
- すべての期間の残量が未取得でも、サービス自体を非表示にはしません。
- 数値エラーと更新失敗は未取得とは区別します。他サービスから取得した公式の0%は
  0%として維持します。
- 設定上限から残量を計算する他サービスでは、「約」を付けて公式値と区別します。

カード、メニューバー、macOSのWidget、設定、ヘルプでこの区別を共通にします。
旧WidgetスナップショットのGemini算出割合は、公式値として再利用せず未取得へ移行します。

## 検証の範囲

合成データで、transcript間の重複、JSONキー順、片側限定イベント、同一ファイルの反復、
別セッション、参考コストの一致を検証できる構成です。表示側は、公式0%、未取得、
数値エラー、更新失敗、利用量OFF／ON、旧スナップショットの移行・保存再読込を確認対象とします。

合成データや描画のテストは、実サービスの公式残量を取得できることの証明ではありません。
OSのWidgetKitによる実表示、VoiceOverの音声、IntelやmacOS 14での実行、利用者の理解評価は
それぞれ実環境での確認が必要です。
